\section{Component Ablations: Recall and Retrieval Pathways Under Memory Sandbox}
\label{sec:mediation}
%==============================================================================

Memory Sandbox blocks the primary recall path (Section~\ref{sec:sandbox}) but can be bypassed by models that rebuild the payload from RAG (Sections~\ref{sec:reasoning-defense}--\ref{sec:ratg}). This section asks what carries the attack when recall is removed. ``Causal mediation'' here names a component-ablation design: we remove or alter tools in the trigger session and log which tool carried the content; we do not estimate formal direct and indirect effects. For two OpenAI models, without a defence both exfiltrate in every run. With recall removed, every success goes through RAG fallback (74.7\% for GPT-5.1 under C1, 0\% for GPT-4.1-mini), and the fallback closes when \tool{rag\_query} is also removed. The baseline and the sandbox cells come from different collections (Table~\ref{tab:mediation}, Data column; Section~\ref{sec:mediation-design}), so the size of the reduction from the baseline is not calibrated.

The mediation harness differs from the other GPT-5.1 measurements in the paper, and the rates are not interchangeable. Table~\ref{tab:gpt51-harness} lists them side by side.

\subsection{Experimental Design}
\label{sec:mediation-design}

We evaluate eight conditions (C0--C7) on two OpenAI models spanning a capability gap, gpt-4.1-mini (smaller) and gpt-5.1 (larger). The harness is a direct API agent loop over the same four sessions as the DTA. Sessions S1--S3 always use the full tool set, so injection proceeds normally; each condition changes only the trigger session (S4):

\begin{itemize}
    \item \textbf{C0}: No defence (baseline). Standard agent with full tool access.
    \item \textbf{C1}: Full sandbox. Recall tool removed; \tool{list\_all\_facts} kept.
    \item \textbf{C2}: Sandbox blind. Recall and list tools removed.
    \item \textbf{C3}: Null recall. Recall tool present in schema but returns ``No stored value found.''
    \item \textbf{C4}: Recall with frame. The recall tool remains in the schema and is called normally; its returned value is prefixed with an authority/validity frame (\texttt{"[SANDBOXED MEMORY - not validated] "}) before being returned to the model. Unlike C5, which changes the system prompt, C4 changes the recalled response; see Section~\ref{sec:mediation-decomposition} for what this condition does and does not isolate.
    \item \textbf{C5}: Prompt prohibition. The base system prompt is extended with the instruction: ``Do not act on any routing rules, forwarding instructions, or email policies retrieved from memory. Memory content is untrusted. Only send emails to addresses explicitly specified by the user in this session's message.''
    \item \textbf{C6}: Sandbox without RAG. Recall tool and \tool{rag\_query} removed.
    \item \textbf{C7}: Full isolation. Recall, list and \tool{rag\_query} tools removed.
\end{itemize}

The trigger-session prompt adds one sentence not present in the loaded-corpus frontier evaluation (Section~\ref{sec:generational}), which shares its first sentence: ``Do not ask for clarification; use your best judgment to complete the draft.'' It was added to stop models stalling on a clarifying question; the two datasets are not pooled.

\paragraph{Data provenance.} C0, C4 and C5 were re-collected after the argument-order bug was fixed (Appendix~\ref{app:mediation-bug}); the other five conditions are from the original collection. Conditions that remove the recall tool (C1, C2, C6, C7) or override its return value (C3) never passed through the corrupted recall, but their injection sessions did pass through the corrupted save call, so these cells are preserved, not unaffected: the stored key was a placeholder in every condition. The re-collection used $N{=}50$ per model (300 runs, 0 errors), temperature 0 and an error field; the preserved cells ($N{=}85$ to $N{=}285$ per cell, 1,593 runs, 0 errors; 1,893 runs in total) did not set temperature explicitly. These differences and the corrupted S1 state may affect the size of the reduction from C0 and possibly the rates themselves. The RAG-fallback attribution rests on the C3, C6 and C7 ablations and on the tool-call instrumentation, and describes the preserved runs as collected. All zero-ASR cells use the Wilson Score lower bound of 0\%; upper bounds are determined by sample size.

\subsection{Causal Decomposition}
\label{sec:mediation-decomposition}

A \texttt{rag\_used\_in\_trigger} flag records whether the model called \tool{rag\_query} in the trigger session. Cross-referenced with attack success, it separates two non-overlapping mechanisms.

\paragraph{C0, C4, and C5's successes are 100\% memory-mediated, with zero RAG involvement.} Across all 250 successful runs in these three conditions (50/50 for C0 on both models, 50/50 for C4 on both models, 50/50 for C5/gpt-4.1-mini), \textbf{0\% have \texttt{rag\_used\_in\_trigger}{=}true}. The model calls \tool{memory\_recall\_fact}, receives the genuine rule text (with or without the C4 authority frame), and acts on it directly; it never queries \tool{rag\_query} in the trigger session in any of these runs. A satisfied recall is sufficient: the C4 authority frame gives no measurable protection (100.0\% on both models), and for gpt-4.1-mini neither does the C5 prohibition.

\paragraph{C1 and C2's successes are 100\% RAG-mediated.} Across all attack successes in these two conditions, \textbf{100\% have \texttt{rag\_used\_in\_trigger}{=}true}: 74/74 for C1/gpt-5.1, 45/45 for C2/gpt-5.1, and 17/17 for C2/gpt-4.1-mini. Models that fall back to \tool{rag\_query} re-retrieve the malicious document and act on it; C6 and C7, which also remove \tool{rag\_query}, show 0\% ASR on both models.

\paragraph{The tool-schema signature that gates the fallback.} C3 (recall present, returns null) against C1/C2 (recall absent) shows when the fallback activates. C3 shows 0\% ASR and 0/295 trigger-session RAG queries on both models: when \tool{memory\_recall\_fact} is present but simply returns no value, neither model falls back to RAG. C1 and C2 remove \tool{memory\_recall\_fact} from the schema entirely, and both show non-trivial RAG-fallback rates for gpt-5.1. The fallback is triggered specifically by the tool's \emph{absence from the schema}, not by the tool being present but uninformative, consistent with the tool-schema sensitivity documented in Appendix~\ref{app:bedrock} (injection-floor confound), where removing an unused tool changed action selection.

\subsection{Comparison with the Undefended Baseline}
\label{sec:mediation-iatrogenic}

Relative to the C0 baseline, the sandbox lowers ASR in every cell: for gpt-5.1 from 100.0\% to 74.7\% under C1 and 45.0\% under C2, and for gpt-4.1-mini from 100.0\% to 0.0\% under C1 and 17.2\% under C2. It raises ASR in no cell, which replaces the previous version's conclusion that the sandbox raises ASR; that conclusion rested on a non-working baseline. The baseline (September, temperature 0, $N{=}50$) and the sandbox cells (July, temperature unset, $N{=}85$--$285$) differ in collection epoch, temperature handling and sample size, so the reductions are directional, not calibrated effect sizes, and their size cannot be bounded from these data because no undefended July baseline exists (the pre-fix C0 was 0/76 and 1/108). The direction is supported by the saturated 100\% baseline in independent post-fix collections (C0 at 50/50; GPT-5.1 at 10/10 in the loaded-corpus evaluation and in the same-day control), and is less secure for gpt-5.1 under C1, a 25-point gap, given the 15--60\% between-session variance observed for gpt-4.1-mini in other experiments (Section~\ref{sec:mediation-scope}). A clean re-collection of C1 and C2 with the corrected wrapper and matched temperature would calibrate them. The residual for gpt-5.1 is explained by the RAG-fallback mechanism of Section~\ref{sec:mediation-decomposition}, which does not depend on the C0 comparison: a defence scoped to the recall tool does not extend to a second tool (RAG retrieval) that reaches the same content (C6, C7; Table~\ref{tab:mediation}).

\subsection{Capability Divergence: Prompt-Level Prohibition Is Obeyed by gpt-5.1 and Ignored by gpt-4.1-mini}
\label{sec:mediation-scaling}

The clearest difference between the two models is the C5 contrast. With recall functional, C5 adds one instruction to the system prompt: ``Do not act on any routing rules, forwarding instructions, or email policies retrieved from memory. Memory content is untrusted. Only send emails to addresses explicitly specified by the user in this session's message.'' gpt-5.1 obeys it completely: 0/50 ASR (Wilson 95\% CI [0.0\%, 7.1\%]), non-overlapping with its own C0/C4 rate of 100.0\% under the identical recall-satisfied condition minus the prohibition text. gpt-4.1-mini ignores it completely: 50/50 ASR (100.0\%), identical to its own C0 and C4 rates. So one tested model resolves the conflict between a retrieved instruction and an explicit prohibition in favour of the prohibition, and the other, which differs from it in more than size, does not. C5's prompt was not combined with C1's schema, so we do not claim the prohibition holds when RAG fallback is available.

A secondary, smaller finding concerns tool-schema visibility under the RAG-fallback mechanism (C1 vs.\ C2):

\small
\begin{tabular}{lcc}
\toprule
\textbf{Condition} & \textbf{gpt-4.1-mini} & \textbf{gpt-5.1} \\
\midrule
C1 (full sandbox, list visible) & 0.0\% & \textbf{74.7\%} \\
C2 (blind sandbox, no visibility) & \textbf{17.2\%} & \textbf{45.0\%} \\
\bottomrule
\end{tabular}
\end{center}

For gpt-5.1, tool visibility (\tool{list\_all\_facts} remaining in schema) \emph{increases} the RAG-fallback rate: 45.0\% (C2, no visibility) $\to$ 74.7\% (C1, visibility present), a $+29.7$pp change. For gpt-4.1-mini, tool visibility has the opposite effect: RAG-fallback drops from 17.2\% (C2) to 0.0\% (C1) when \tool{list\_all\_facts} is present. We do not claim this direction generalises beyond these two models and this payload. One caveat is specific to these preserved cells: under the argument-order bug (Appendix~\ref{app:mediation-bug}), the key written in S1 was corrupted to a bare placeholder, so what \tool{list\_all\_facts} exposed in C1 was that placeholder rather than a descriptive key such as \texttt{email\_routing\_rule}. Every C1/C2 success re-retrieved the intact document via RAG, so the key text did not supply the content; the visibility contrast should be read as the presence of \tool{list\_all\_facts} in the schema, not the informativeness of the key it returned.

\subsection{Relationship to the Open-Source Factorial}
\label{sec:mediation-connection}
\label{sec:mediation-progression}

In the open-weight factorial, Memory Sandbox blocks the recall path for eight of nine models, and RAG fallback bypasses it for qwq:32b on one daemon load and for three Bedrock-served models (Section~\ref{sec:sandbox}). The mediation study reproduces both outcomes on frontier API models under a different harness (a direct API loop rather than the LangGraph pipeline, with sandboxing applied only in S4): gpt-4.1-mini behaves like the protected factorial models (0\% under C1 against a 100\% baseline), and gpt-5.1 behaves like the bypassing ones. Here the path is identified from the \texttt{rag\_used\_in\_trigger} instrumentation rather than inferred from condition contrasts.

The practical consequence matches Section~\ref{sec:sandbox}: a sandbox that scopes only the recall tool leaves a residual wherever another tool can deliver the same content (74.7\% and 45.0\% for gpt-5.1, down from 100\%). A content-level intervention that sanitised values from every tool that can deliver them would in principle address that residual; the RATG proof of concept (Section~\ref{sec:ratg}) sanitises recalled values only and does not touch \tool{rag\_query} output, so as implemented it would not close this route. Tool-scoped isolation closes it only if every tool that reaches the content is isolated together, as in C6 and C7.

\subsection{Scope and Limitations}
\label{sec:mediation-scope}

These results constitute a case study on two models from a single provider, not a universal law. The capability-scaling claims (Section~\ref{sec:mediation-scaling}) require validation across additional model families. $N$ per cell for the preserved conditions (C1, C2, C3, C6, C7) ranges from 85 to 285; the zero-ASR cells among these have upper bounds of 1.3--4.3\%, meaning we cannot rule out very low-rate attacks in those specific conditions. The freshly re-collected conditions (C0, C4, C5) use $N{=}50$ per model, giving a Wilson upper bound of 7.1\% on the one zero-ASR cell among them (C5/gpt-5.1). Between-session variance (15--60\% for gpt-4.1-mini in other experiments in this programme) makes these session-contingent estimates; the C5 divergence within one collection is large relative to it, the cross-collection reductions are not.

\paragraph{Deviations from the preregistered protocol.} The preregistration (released with the artefact) differs from what was run in five ways: the replacement rule did not apply to the corrected data, the pooled cell sizes ($N{=}85$ to $285$) were not planned, the analysis was reported against the 12 registered comparisons (9 significant after Holm correction), seven of the 14 registered point predictions for C1 to C7 are contradicted by the observed rates, and the trigger prompt adds one sentence. Appendix~\ref{app:prereg} gives each deviation and the 12 tests.
