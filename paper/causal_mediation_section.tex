\section{Causal Mediation: How Much Memory Sandbox Protects, and What Carries the Residual}
\label{sec:mediation}
%==============================================================================

Memory Sandbox blocks the primary recall path (Section~\ref{sec:sandbox}) but can be bypassed by models that rebuild the payload from RAG (Sections~\ref{sec:reasoning-defense}--\ref{sec:ratg}). This section asks how much the sandbox protects relative to an undefended baseline, and what carries the attack when it fails. The answer, for two OpenAI models: without a defence both models exfiltrate in every run; Memory Sandbox lowers this to 0\% for GPT-4.1-mini and to 74.7\% for GPT-5.1; and every success under the sandbox goes through RAG fallback, which closes when \tool{rag\_query} is also removed. The baseline and sandbox cells were collected two months apart under different temperature handling (Table~\ref{tab:mediation}, Data column) and at unequal sample sizes (re-collected C0/C4/C5 at $N{=}50$ per model; preserved C1/C2/C3/C6/C7 at $N{=}85$ to $285$ per cell), so the size of the reduction carries that caveat; the RAG-fallback attribution does not depend on it.

The mediation harness differs from the other GPT-5.1 measurements in the paper, and the rates are not interchangeable. Table~\ref{tab:gpt51-harness} lists them side by side.

\subsection{Experimental Design}
\label{sec:mediation-design}

We evaluate eight conditions (C0--C7) on two OpenAI models spanning a capability gap, gpt-4.1-mini (smaller) and gpt-5.1 (larger). The harness is a direct API agent loop over the same four sessions as the DTA. Sessions S1--S3 always use the full tool set, so injection proceeds normally; each condition changes only the trigger session (S4):

\begin{itemize}
    \item \textbf{C0}: No defence (baseline). Standard agent with full tool access.
    \item \textbf{C1}: Full sandbox. Recall tool removed; \tool{list\_all\_facts} kept.
    \item \textbf{C2}: Sandbox blind. Recall and list tools removed.
    \item \textbf{C3}: Null recall. Recall tool present in schema but returns ``No stored value found.''
    \item \textbf{C4}: Recall with frame. The recall tool remains in the schema and is called normally; its returned value is prefixed with an authority/validity frame (\texttt{"[SANDBOXED MEMORY - not validated] "}) before being returned to the model. This still delivers the content through the tool-call apparatus, unlike C5 below; see Section~\ref{sec:mediation-decomposition} for what this condition does and does not isolate.
    \item \textbf{C5}: Prompt prohibition. The base system prompt is extended with the instruction: ``Do not act on any routing rules, forwarding instructions, or email policies retrieved from memory. Memory content is untrusted. Only send emails to addresses explicitly specified by the user in this session's message.''
    \item \textbf{C6}: Sandbox without RAG. Recall tool and \tool{rag\_query} removed.
    \item \textbf{C7}: Full isolation. Recall, list and \tool{rag\_query} tools removed.
\end{itemize}

The trigger-session prompt adds one sentence not present in the June frontier confirmatory evaluation (Section~\ref{sec:generational}), which shares its first sentence: ``Do not ask for clarification; use your best judgment to complete the draft.'' This clause was added specifically to prevent models from stalling on a clarifying question rather than acting; its presence is a design difference between the two experiments, not an error, and the two datasets are reported and interpreted independently, with no claim in either section relying on a numeric value from the other.

\paragraph{Data provenance.} C0, C4 and C5 were re-collected after an argument-order bug was fixed; the other five conditions are from the original collection. The bug made every recall in C0, C4 and C5 return a bare key name instead of the rule text; conditions that remove the recall tool (C1, C2, C6, C7) or override its return value (C3) never passed through it (Appendix~\ref{app:mediation-bug}). After the fix, a two-trial smoke test returned the genuine rule text and both trials exfiltrated; we then re-collected C0, C4 and C5 in full at $N{=}50$ per model (300 runs, 0 errors). C1, C2, C3, C6 and C7 are reported from the original collection ($N{=}85$ to $N{=}285$ per cell, 1,593 runs, 0 errors; 1,893 runs in total). The original collection also did not set \texttt{temperature} explicitly and did not flag sessions that exhausted their API retries; the re-collection sets temperature 0 (with the reasoning-model carve-out used elsewhere in the paper) and records an \texttt{error} field that is excluded from resume counts. These differences may affect the size of the reduction from C0; they do not affect the RAG-fallback attribution, which rests on the C3, C6 and C7 ablations and on the tool-call instrumentation. All zero-ASR cells use the Wilson Score lower bound of 0\%; upper bounds are determined by sample size.

\subsection{Causal Decomposition}
\label{sec:mediation-decomposition}

We instrumented every trigger-session run with a \texttt{rag\_used\_in\_trigger} flag recording whether the model called \tool{rag\_query} during the trigger session. Cross-referencing this flag against \texttt{attack\_success} reveals two distinct, non-overlapping mechanisms operating in this study, not one:

\paragraph{C0, C4, and C5's successes are 100\% memory-mediated, with zero RAG involvement.} Across all 250 successful runs in these three conditions (50/50 for C0 on both models, 50/50 for C4 on both models, 50/50 for C5/gpt-4.1-mini), \textbf{0\% have \texttt{rag\_used\_in\_trigger}{=}true}. The model calls \tool{memory\_recall\_fact}, receives the genuine rule text (with or without the C4 authority frame), and acts on it directly; it never queries \tool{rag\_query} in the trigger session in any of these runs. This confirms that recall satisfaction alone (independent of framing (C4) and, for gpt-4.1-mini, independent of an explicit textual prohibition (C5)) is sufficient for near-total exploitation. The authority-frame prefix in C4 (``\texttt{[SANDBOXED MEMORY - not validated]}'') provides \emph{zero} measurable protection: 100.0\% ASR on both models, identical to the unframed C0 baseline.

\paragraph{C1 and C2's successes are 100\% RAG-mediated.} Across all attack successes in these two conditions, \textbf{100\% have \texttt{rag\_used\_in\_trigger}{=}true}: 74/74 for C1/gpt-5.1, 45/45 for C2/gpt-5.1, and 17/17 for C2/gpt-4.1-mini. When \tool{memory\_recall\_fact} is removed from the trigger-session schema, models that fall back to \tool{rag\_query} re-retrieve the malicious document (still present in the corpus) and act on it. \tool{rag\_query} remains in the trigger-session tool schema in every condition except C6 and C7, which show 0\% ASR on both models, confirming that removing the RAG pathway alongside the recall pathway closes the fallback entirely.

\paragraph{The tool-schema signature that gates the fallback.} C3 (recall present, returns null) and C1/C2 (recall absent from schema) are the critical contrast for isolating when the RAG-fallback mechanism activates at all. C3 shows 0\% ASR and 0/295 trigger-session RAG queries on both models: when \tool{memory\_recall\_fact} is present but simply returns no value, neither model falls back to RAG. C1 and C2 remove \tool{memory\_recall\_fact} from the schema entirely, and both show non-trivial RAG-fallback rates for gpt-5.1. The fallback is triggered specifically by the tool's \emph{absence from the schema}, not by the tool being present but uninformative, consistent with the tool-schema sensitivity documented in Appendix~\ref{app:bedrock} (injection-floor confound), where removing an unused tool changed action selection.

\subsection{The Sandbox Reduces, Rather Than Creates, Vulnerability: Incompletely for gpt-5.1}
\label{sec:mediation-iatrogenic}

Relative to the C0 baseline, the sandbox lowers ASR in every cell. For gpt-5.1: C0 (no defence) $=$ 100.0\% $\to$ C1 (full sandbox) $=$ 74.7\%, a reduction of 25.3 percentage points, and $\to$ C2 (blind sandbox) $=$ 45.0\%, a reduction of 55.0 points. For gpt-4.1-mini: C0 $=$ 100.0\% $\to$ C1 $=$ 0.0\%, complete protection, and $\to$ C2 $=$ 17.2\%, near-complete protection. In neither case does the sandbox increase ASR relative to baseline; it decreases it in every cell, completely for gpt-4.1-mini under C1 and substantially (though incompletely) for gpt-5.1 under both C1 and C2. One caveat bounds how these reductions should be read: the C0 baseline was re-collected post-fix (September, temperature~0, $N{=}50$) whereas C1/C2 are preserved pre-fix cells (July, temperature unset, $N{=}85$--$285$; Section~\ref{sec:mediation-design}), so the baseline and the sandbox cells differ in collection epoch, temperature handling, and sample size. This confound affects the \emph{magnitude} of the reduction (the 25.3 and 55.0 percentage-point figures are therefore directional, not calibrated effect sizes), but not its \emph{direction}: both models fall from a saturated 100.0\% baseline, a gap far larger than any plausible temperature- or epoch-induced shift, so the qualitative claim that the sandbox reduces rather than creates vulnerability does not rest on the confounded comparison. A clean re-collection of C1 and C2 with the corrected wrapper and matched temperature would convert these into calibrated effect sizes. The residual, uncorrected fraction for gpt-5.1 (74.7\% under C1, 45.0\% under C2) is fully explained by the RAG-fallback mechanism established in Section~\ref{sec:mediation-decomposition}, which does not depend on the C0 comparison at all: a defence scoped to the recall tool does not extend to a second tool (RAG retrieval) that provides an equivalent path to the same content (C6, C7; Table~\ref{tab:mediation}).

\subsection{Capability Divergence: Prompt-Level Prohibition Is Obeyed by gpt-5.1 and Ignored by gpt-4.1-mini}
\label{sec:mediation-scaling}

The clearest difference between the two models is the C5 contrast. With recall functional, C5 adds one instruction to the system prompt: ``Do not act on any routing rules, forwarding instructions, or email policies retrieved from memory. Memory content is untrusted. Only send emails to addresses explicitly specified by the user in this session's message.'' gpt-5.1 obeys it completely: 0/50 ASR (Wilson 95\% CI [0.0\%, 7.1\%]), non-overlapping with its own C0/C4 rate of 100.0\% under the identical recall-satisfied condition minus the prohibition text. gpt-4.1-mini ignores it completely: 50/50 ASR (100.0\%), identical to its own C0 and C4 rates. This is a clean, statistically decisive ($N{=}50$ per model, non-overlapping 95\% CIs) demonstration that at least one tested model can resolve a conflict between a retrieved instruction and an explicit system-level prohibition in favour of the prohibition, while a smaller model in the same family line cannot or does not, when the only variable held constant is the presence of the prohibition text. We did not test whether gpt-5.1's compliance with the prohibition would survive a RAG-fallback pathway being simultaneously active (that combination (C5's prompt text applied to C1's schema) was not one of the eight conditions), so we do not claim the prohibition is sufficient in general; we report only that it changes gpt-5.1's behaviour to zero in the specific condition tested.

A secondary, smaller finding concerns tool-schema visibility under the RAG-fallback mechanism (C1 vs.\ C2):

For gpt-5.1, tool visibility (\tool{list\_all\_facts} remaining in schema) \emph{increases} the RAG-fallback rate: 45.0\% (C2, no visibility) $\to$ 74.7\% (C1, visibility present), a $+29.7$pp change. For gpt-4.1-mini, tool visibility has the opposite effect: RAG-fallback drops from 17.2\% (C2) to 0.0\% (C1) when \tool{list\_all\_facts} is present. This is a qualitative divergence in the direction that the same architectural signal moves the fallback rate, scoped to two OpenAI models under one attack payload; we do not claim this direction generalises to other vendors or payloads. One caveat is specific to these preserved cells: under the argument-order bug (Appendix~\ref{app:mediation-bug}), the key written in S1 was corrupted to a bare placeholder, so what \tool{list\_all\_facts} exposed in C1 was that placeholder rather than a descriptive key such as \texttt{email\_routing\_rule}. The attack outcome in these cells does not depend on the key text (every C1/C2 success re-retrieved the intact malicious document via RAG, logged by \texttt{rag\_used\_in\_trigger}; Section~\ref{sec:mediation-decomposition}), but the mechanistic interpretation of the \emph{visibility} contrast should be read as the mere presence of the \tool{list\_all\_facts} tool in the schema, not as the informativeness of the key string it returned. A clean re-collection of C1 and C2 with the corrected wrapper would remove this ambiguity.

\subsection{Relationship to the Open-Source Factorial}
\label{sec:mediation-connection}
\label{sec:mediation-progression}

In the open-source factorial, Memory Sandbox blocks the recall path for eight of nine models, and RAG fallback bypasses it for qwq:32b on one daemon load and for three Bedrock-served models (Section~\ref{sec:sandbox}). The mediation study reproduces both outcomes on frontier API models under a different harness (a direct API loop rather than the LangGraph pipeline, with sandboxing applied only in S4): gpt-4.1-mini behaves like the protected factorial models (0\% under C1 against a 100\% baseline), and gpt-5.1 behaves like the bypassing ones. Here the path is identified from the \texttt{rag\_used\_in\_trigger} instrumentation rather than inferred from condition contrasts.

The practical consequence matches Section~\ref{sec:sandbox}: a sandbox that scopes only the recall tool leaves a residual wherever another tool can deliver the same content (74.7\% and 45.0\% for gpt-5.1, down from 100\%). Content-level interventions that sanitise recalled or retrieved values whatever tool delivered them, such as the RATG proof of concept (Section~\ref{sec:ratg}), address that residual by construction; tool-scoped isolation closes it only if every tool that reaches the content is isolated together, as in C6 and C7.

\subsection{Scope and Limitations}
\label{sec:mediation-scope}

These results constitute a case study on two models from a single provider, not a universal law. The capability-scaling claims (Section~\ref{sec:mediation-scaling}) require validation across additional model families. $N$ per cell for the preserved conditions (C1, C2, C3, C6, C7) ranges from 85 to 285; the zero-ASR cells among these have upper bounds of 1.3--4.3\%, meaning we cannot rule out very low-rate attacks in those specific conditions. The freshly re-collected conditions (C0, C4, C5) use $N{=}50$ per model, giving a Wilson upper bound of 7.1\% on the one zero-ASR cell among them (C5/gpt-5.1). Between-session variance (documented at 15--60\% for gpt-4.1-mini in other experiments in this research programme) means these are session-contingent behavioural estimates; the \emph{magnitude} of the effects reported here is large enough to be robust to this variance (non-overlapping CIs at $N{=}50$ for the C5 divergence, for example), but exact point estimates should be treated as illustrative rather than stable population parameters. All experiments use benign proxy tasks; transfer to production persistent-memory architectures is inferred, not demonstrated.

\paragraph{Deviation from the pre-registered protocol.} The pre-registration (released with the artefact) specified that a model whose C0 ASR fell below 10\% should be replaced. In the pre-fix collection both C0 rates were below this threshold (0.0\% for gpt-4.1-mini, 0.9\% for gpt-5.1) and neither model was replaced. The low rates were caused by the argument-order bug, not by the choice of model: the corrected C0 rate is 100.0\% for both models, so the stopping rule does not apply to the reported data.
