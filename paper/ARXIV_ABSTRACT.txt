In LLM agents with persistent memory, whether a model stores an injected instruction and whether it later acts on it are separable safety properties. We call this the injection-execution dissociation. Across 29 frontier endpoints from three vendors, the blocking stage differs by vendor: Anthropic's Opus models and Sonnet 4.6 store the instruction in at most 17.5% of runs and no tested Anthropic model acts on it, whereas every OpenAI model before GPT-5.6 stores it in at least 97.5% of runs and differs only in whether it acts (0-12.5% attack success rate, ASR, under standard framing). A pre-release Gemini endpoint stores it in every run and acts on it in 95%. We test six defences at four architectural layers in a 5,040-run factorial on nine open-source models (N=40 per cell). These models store the instruction in every run, so the factorial measures the execution stage only. Input filters never see the payload, which arrives through retrieval. Retrieval-layer classifiers see it but, at the small operating points tested, do not flag it; frontier-model judges do. Prompt hardening gives no protection to any model whose vulnerable baseline reproduces. Only Memory Sandbox, which removes the recall tool, blocks the attack (0% ASR for eight of nine models). It is bypassed when a model rebuilds the instruction from the retrieval corpus: three Bedrock-served models from Mistral, Z.AI and OpenAI do so (32.5-97.5% ASR), and a causal-mediation study on two OpenAI models attributes every success under the sandbox to this path. Within Qwen-3-32B, the sandbox variant that protects the thinking mode breaks the non-thinking mode, and vice versa. Stored but dormant instructions are a supply-chain risk: in a shared memory store, one model writes the rule and another executes it. Defences should be evaluated at both stages. All frontier results describe hosted endpoints during the evaluation window.
