### Step-by-Step Explanation of Compiler Stages

#### **1. Lexing (Tokenization)**
**Purpose**: Split the source code into a sequence of meaningful **tokens**, which are the smallest units of the language (e.g., keywords, identifiers, operators, literals).

**Example Code**:
```c
int x = 5 + 3 * 2;
```

**Process**:
1. **Input**: The raw source code string.
2. **Lexer Operation**:
   - Uses **regular expressions** to match patterns and categorize characters into tokens.
   - **Token Types**:
     - `KEYWORD` (e.g., `int`).
     - `IDENTIFIER` (e.g., `x`).
     - `OPERATOR` (e.g., `=`, `+`, `*`).
     - `INTEGER_LITERAL` (e.g., `5`, `3`, `2`).
     - `PUNCTUATOR` (e.g., `;`).
3. **Output**: A list of tokens with their types and values:
   ```
   [int, x, =, 5, +, 3, *, 2, ;]
   ```

**Tools/Algorithms**:
- **Lexical Analyzers**: Tools like `lex` (Flex) or ANTLR generate lexers from regular expressions.
- **Deterministic Finite Automaton (DFA)**: Used to recognize token patterns efficiently.

---

#### **2. Parsing**
**Purpose**: Analyze the sequence of tokens to ensure they form valid **syntactic structures** according to the language's grammar. Builds a **parse tree**.

**Example Code**:
```c
int add(int a, int b) { return a + b; }
```

**Process**:
1. **Input**: Token stream from lexing.
2. **Parsing Algorithm**:
   - Uses a **context-free grammar (CFG)** to define valid syntax.
   - **Parser Types**:
     - **LL(k)**: Top-down, leftmost derivation.
     - **LR(k)**: Bottom-up, rightmost derivation (common in tools like `yacc`/`bison`).
3. **Parse Tree Construction**:
   - Example for `a + b`:
     ```
     BinaryExpression
       /     \
     a       b
      \     /
      +   (operator)
     ```
4. **Output**: A parse tree representing the code's structure.

**Tools/Algorithms**:
- **Parser Generators**: `yacc`, `ANTLR`, or `LL(*)` parsers.
- **Error Recovery**: Handles syntax errors (e.g., mismatched parentheses).

---

#### **3. Abstract Syntax Tree (AST) Construction**
**Purpose**: Simplify the parse tree into an **AST**, which discards unnecessary syntactic details (e.g., parentheses) and focuses on semantic meaning.

**Example Code**:
```c
return a + b;
```

**Process**:
1. **Input**: Parse tree.
2. **AST Construction**:
   - Removes redundant nodes (e.g., parentheses in expressions).
   - Example AST for `a + b`:
     ```
     ReturnStatement
       └─ BinaryExpression
           ├─ Identifier: a
           └─ Identifier: b
     ```
3. **Output**: An AST that captures the code's logical structure.

**Tools/Algorithms**:
- **Recursive Descent Parsing**: Builds AST during parsing.
- **Visitor Pattern**: Used to traverse and manipulate the AST.

---

#### **4. Type Checking**
**Purpose**: Ensure all operations are **type-safe** (e.g., no adding a string to an integer).

**Example Code**:
```c
int x = 5; // Valid
float y = "hello"; // Invalid (type mismatch)
```

**Process**:
1. **Input**: AST.
2. **Type System**:
   - **Static Typing**: Types are inferred/declared at compile time.
   - **Type Inference**: Deduces types without explicit declarations (e.g., in functional languages).
3. **Checking Steps**:
   - **Variable Declarations**: Check `int x` is valid.
   - **Expressions**: Ensure `5` (integer) matches `x`'s type.
   - **Function Calls**: Verify arguments match parameter types.
4. **Output**: Error messages if type mismatches exist.

**Tools/Algorithms**:
- **Type Systems**: Hindley-Milner for functional languages, or simple static checks for C-like languages.
- **Symbol Tables**: Track variable types and scopes.

---

#### **5. Intermediate Representation (IR)**
**Purpose**: Convert the AST into a **lower-level form** (IR) for easier optimization and code generation.

**Example Code**:
```c
int x = 5 + 3 * 2;
```

**Process**:
1. **Input**: AST.
2. **Common IR Forms**:
   - **Three-Address Code (TAC)**:
     ```
     t1 = 3 * 2
     t2 = 5 + t1
     x = t2
     ```
   - **Static Single Assignment (SSA)**:
     ```
     t1 = 3 * 2
     t2 = 5 + t1
     x = t2
     ```
3. **Output**: IR that abstracts away language-specific syntax.

**Tools/Algorithms**:
- **LLVM IR**: A popular IR used in modern compilers.
- **Graph-Based IRs**: Represent control flow and data flow explicitly.

---

#### **6. Optimization Passes**
**Purpose**: Improve the IR's efficiency (speed, memory, power) without changing its behavior.

**Example Code**:
```c
int sum(int n) {
    int s = 0;
    for (int i = 0; i < n; i++) {
        s += i;
    }
    return s;
}
```

**Optimization Techniques**:
1. **Constant Folding/Propagation**:
   - Replace `3 * 2` with `6`.
2. **Dead Code Elimination**:
   - Remove unused variables.
3. **Loop Optimization**:
   - **Loop Unrolling**: Duplicate loop bodies to reduce overhead.
   - **Strength Reduction**: Replace `i * 2` with `i << 1`.
4. **Common Subexpression Elimination**:
   - Reuse results of repeated expressions.
5. **Peephole Optimization**:
   - Optimize small code sequences (e.g., `add; sub` → `sub`).

**Example After Optimization**:
- Original loop:
  ```
  for i from 0 to n: s += i
  ```
- Optimized (using formula `n*(n-1)/2`):
  ```
  s = n * (n - 1) / 2
  ```

**Tools/Algorithms**:
- **Data Flow Analysis**: Tracks variable values across the program.
- **Register Allocation**: Assigns variables to CPU registers.

---

#### **7. Code Generation**
**Purpose**: Translate the optimized IR into **target machine code** (e.g., x86, ARM).

**Example Code**:
```c
int add(int a, int b) { return a + b; }
```

**Process**:
1. **Input**: Optimized IR.
2. **Target Architecture**:
   - **Instruction Set**: Choose instructions (e.g., `ADD`, `MOV`).
   - **Calling Convention**: Define how parameters are passed (e.g., stack vs. registers).
3. **Code Generation Steps**:
   - **Register Allocation**: Assign variables to CPU registers.
   - **Instruction Selection**: Map IR operations to machine instructions.
   - **Assembly Code**:
     ```
     add:
         mov eax, [ebp+8]  ; Load a into EAX
         add eax, [ebp+12] ; Add b to EAX
         ret
     ```
4. **Output**: Machine code (binary) or assembly code (text).

**Tools/Algorithms**:
- **Assembly Generators**: Tools like `gas` (GNU Assembler).
- **Peephole Optimization**: Final tweaks to machine code.

---
